1. 준비물

  • ESP32-S3 개발 보드
  • 데이터 통신이 가능한 USB 케이블
  • Linux PC와 설치 완료된 ESP-IDF
  • 터미널 및 텍스트 편집기
USB 케이블 주의
충전 전용 케이블은 전원만 공급하고 시리얼 장치를 만들지 않는다. 포트가 나타나지 않으면 먼저 다른 데이터 케이블과 USB 포트를 시험한다.

2. ESP-IDF 환경 활성화

이 개발 환경에 설치된 ESP-IDF v6.0.2는 다음 명령으로 활성화한다.

source /home/user/.espressif/v6.0.2/esp-idf/export.sh
idf.py --version

정상이라면 다음과 비슷하게 출력된다.

ESP-IDF v6.0.2
새 터미널을 열 때마다 export.sh를 다시 실행해야 한다. idf.py: command not found가 보이면 가장 먼저 환경 활성화 여부를 확인한다.

3. 새 프로젝트 생성

작업용 디렉터리로 이동한 다음 idf.py create-project를 실행한다.

mkdir -p ~/esp-projects
cd ~/esp-projects
idf.py create-project esp32s3_demo
cd esp32s3_demo

최소 프로젝트는 대략 다음 구조를 갖는다.

esp32s3_demo/
├── CMakeLists.txt
└── main/
    ├── CMakeLists.txt
    └── esp32s3_demo.c

최상위 CMakeLists.txt

cmake_minimum_required(VERSION 3.16)

include($ENV{IDF_PATH}/tools/cmake/project.cmake)
project(esp32s3_demo)

main/CMakeLists.txt

idf_component_register(
    SRCS "esp32s3_demo.c"
    INCLUDE_DIRS "."
)

4. 최소 동작 코드 작성

main/esp32s3_demo.c를 아래 내용으로 작성한다. 1초마다 카운터를 출력하므로 별도 LED 핀 정보 없이 플래시와 실행 여부를 확인할 수 있다.

#include <inttypes.h>
#include "esp_log.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

static const char *TAG = "esp32s3_demo";

void app_main(void)
{
    uint32_t count = 0;

    while (true) {
        ESP_LOGI(TAG, "Hello ESP32-S3, count=%" PRIu32, count++);
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

5. ESP32-S3 타깃 설정

idf.py set-target esp32s3

이 명령은 프로젝트의 대상을 ESP32-S3로 지정한다. 기존에 다른 타깃으로 생성한 sdkconfig와 빌드 캐시가 있으면 새 타깃에 맞게 재구성된다.

설정 화면 열기

idf.py menuconfig

보드별 Flash 크기, Flash 모드, 콘솔 출력 방식 등 기본값을 확인한 뒤 Save하고 종료한다. 일반 개발 보드에서는 우선 기본값으로 빌드하고, 보드 제조사의 핀맵·Flash 사양과 다를 때만 변경하는 편이 안전하다.

보드 이름과 칩 이름은 다를 수 있다.
제품명에 N16R8 같은 표기가 있더라도 GPIO 배치와 USB 회로는 제조사마다 다르다. 정확한 보드 회로도와 제조사 안내를 함께 확인한다.

6. 프로젝트 빌드

idf.py build

빌드가 성공하면 마지막 부분에 Flash 명령 안내와 바이너리 크기가 출력되고, 프로젝트 아래 build/ 디렉터리에 결과물이 생성된다.

자주 사용하는 빌드 명령

명령용도
idf.py build변경된 부분을 포함해 프로젝트 빌드
idf.py clean일반 빌드 산출물 정리
idf.py fullclean빌드 캐시까지 완전히 정리
idf.py reconfigureCMake 설정을 다시 생성
fullclean은 빌드 디렉터리 내용을 제거하므로 문제 해결이나 타깃 변경처럼 필요한 경우에만 사용한다.

7. USB 시리얼 포트 확인

보드를 연결하기 전과 후에 다음 명령의 결과를 비교한다.

ls /dev/ttyACM* /dev/ttyUSB* 2>/dev/null

일반적으로 네이티브 USB Serial/JTAG 연결은 /dev/ttyACM0, USB-UART 브리지는 /dev/ttyUSB0 형태로 나타난다. 번호는 환경에 따라 달라질 수 있다.

권한 오류가 발생하는 경우

groups
ls -l /dev/ttyACM0

배포판에 따라 사용자를 dialout 또는 uucp 그룹에 추가해야 할 수 있다. 그룹 변경 후에는 로그아웃과 로그인이 필요하다.

8. 보드에 펌웨어 플래시

확인한 포트를 -p 옵션으로 지정한다.

idf.py -p /dev/ttyACM0 flash

USB-UART 장치라면 예를 들어 다음과 같이 실행한다.

idf.py -p /dev/ttyUSB0 flash

자동 다운로드 모드 진입이 안 되는 경우

  1. 보드의 BOOT 버튼을 누른 상태로 유지한다.
  2. RESET/EN 버튼을 짧게 눌렀다 놓는다.
  3. BOOT 버튼을 놓는다.
  4. 다시 idf.py -p 포트 flash를 실행한다.

버튼 명칭과 다운로드 모드 진입 절차는 보드에 따라 다를 수 있다.

9. 로그 모니터링

idf.py -p /dev/ttyACM0 monitor

빌드, 플래시, 모니터를 한 번에 실행할 수도 있다.

idf.py -p /dev/ttyACM0 flash monitor
정상 동작 예
I (...) esp32s3_demo: Hello ESP32-S3, count=0
이후 카운터가 1초마다 증가하면 프로젝트 생성과 플래시가 완료된 것이다.

모니터 종료 단축키는 Ctrl+]이다.

10. 현재 CAN 프로젝트 빌드 및 플래시

이 저장소는 ESP32-S3가 TWAI(Classical CAN) 프레임을 보내는 프로젝트다. 프로젝트 루트에서 다음 순서로 실행한다.

cd /home/user/manta_ws/src/teensy_esp_bridge
source /home/user/.espressif/v6.0.2/esp-idf/export.sh

idf.py set-target esp32s3
idf.py menuconfig
idf.py build
idf.py -p /dev/ttyACM0 flash monitor

이 프로젝트의 기본 CAN 설정

항목기본값연결/설명
TWAI TXGPIO 5외부 CAN 트랜시버의 TXD/D 입력
TWAI RXGPIO 4외부 CAN 트랜시버의 RXD/R 출력
Bitrate500 kbit/s버스의 모든 노드가 동일해야 함
CAN ID0x12311-bit Standard ID
송신 주기100 ms8-byte 프레임 주기 송신

menuconfig → Teensy CAN bridge configuration에서 GPIO, bitrate, CAN ID와 송신 주기를 변경할 수 있다.

CANH/CANL에 GPIO를 직접 연결하면 안 된다.
ESP32-S3의 TWAI는 CAN 컨트롤러이므로 SN65HVD230 같은 3.3 V 로직 호환 외부 CAN 트랜시버가 필요하다. TX GPIO는 트랜시버 TXD로, RX GPIO는 RXD로 연결하고 CAN 버스의 CANH, CANL 및 GND를 각 노드와 연결한다.

11. 문제 해결

증상확인할 내용
idf.py: command not foundexport.sh를 실행해 ESP-IDF 환경을 활성화한다.
시리얼 포트가 없음데이터 케이블, 다른 USB 포트, BOOT 모드, dmesg를 확인한다.
Permission denied장치 소유 그룹과 사용자 그룹을 확인한다.
Failed to connect다른 모니터 프로그램을 닫고 BOOT/RESET으로 다운로드 모드에 진입한다.
타깃 불일치 오류idf.py set-target esp32s3 후 다시 빌드한다.
설정/캐시 오류필요한 경우 idf.py fullclean, idf.py reconfigure를 실행한다.
CAN bus-off수신 노드 ACK, bitrate, CANH/L, 공통 GND, 120 Ω 종단을 확인한다.

CAN 버스 점검

  • 전원을 끈 상태에서 CANH-CANL 저항이 약 60 Ω인지 확인한다.
  • 120 Ω 종단저항은 버스의 물리적인 양 끝에만 설치한다.
  • ESP32-S3 보드의 GPIO 4/5가 다른 기능과 충돌하지 않는지 회로도를 확인한다.
  • CAN 송신은 다른 활성 노드가 ACK해야 정상 완료된다.

12. 최종 체크리스트

  • idf.py --version이 정상 출력된다.
  • 프로젝트 루트에 최상위 CMakeLists.txt가 있다.
  • idf.py set-target esp32s3를 실행했다.
  • idf.py build가 오류 없이 완료됐다.
  • 보드의 실제 시리얼 포트를 확인했다.
  • flash 완료 후 자동 리셋되었다.
  • monitor에서 애플리케이션 로그가 반복 출력된다.
  • CAN 사용 시 트랜시버, 공통 GND, bitrate와 종단저항을 확인했다.
가장 짧은 실행 요약 
source /home/user/.espressif/v6.0.2/esp-idf/export.sh
cd /home/user/manta_ws/src/teensy_esp_bridge
idf.py set-target esp32s3
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
포트 이름은 실제 환경에 맞게 바꾼다.
